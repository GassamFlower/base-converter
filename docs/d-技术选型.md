# d-技术选型：Base Converter

> 依据 Vibe_Coding 立项门。在 `a-立项文档` 和 `c-阶段计划` 基础上定唯一推荐技术栈。
> 关联：`a-立项文档.md`（上游）、`e-架构设计文档.md`（下游）。

---

## 产品形态

- **形态**：纯静态 Web 网站（单页/多页静态 HTML）
- **部署**：Vercel（免费、GSC 友好）
- **维护能力**：单人（个人开发者）

---

## 唯一推荐技术栈

| 层 | 选择 | 说明 |
|---|---|---|
| 前端 | **原生 HTML + CSS + 原生 JS**（少量，零构建） | 无框架、无构建工具 |
| 后端 | **无后端** | 全部转换在浏览器端完成 |
| 数据库 | **无数据库** | 无状态，不需要存储 |
| 部署 | **Vercel**（Git 一个 repo 自动部署） | 免费、HTTPS、快 |
| 领域逻辑 | 原生 JS 的一个通用 `convert()` 函数（BigInt 处理大数） | 见能力清单核心公共模块 |

---

## 为什么这么选（结合本项目）

1. **纯工具、无状态、无账号** → 根本不需要后端和数据库，砍掉最省。
2. **转换逻辑简单** → 进制换算几十行 JS 就能做，用框架反而多一层负担。
3. **"一个关键词一个站"的练手目的** → 技术越简单越聚焦于"跑通流量"本身，符合养网站 = 技术选最笨的原则。
4. **SEO** → 原生静态 HTML 无重 JS 渲染，爬虫直接读到内容，最利于收录。
5. **部署成本趋近零** → 推 repo 到 Vercel 1 分钟上线，无运维。

---

## 为什么淘汰其他方案（至少 3 个）

| 否决方案 | 淘汰理由 |
|---|---|
| **React / Vue / Svelte + 构建工具（Vite）** | 功能单一、无复杂交互，引入框架 = 过度设计，构建产物反而累赘、慢、费心力 |
| **Python / FastAPI / Node（Express）后端 + 数据库** | 无账户、无持久化需求，上后端是最大浪费，还得维护服务器 |
| **Next.js / 全栈框架** | 同样是过度选型，静态纯前端不需要 SSR |
| **付费 / 带后端托管（如 Cloud Ray / 自建 VPS）** | 静态站用免费 Vercel 就够，后者纯浪费钱和精力 |

---

## 选型维度覆盖

- **部署**：Vercel 免费、自动、可靠 ✔
- **维护**：单 HTML 不依赖，随拿随走，风险极低 ✔
- **性能**：原生静态，加载 <1s，全秒响应 ✔
- **生态/社区**：HTML/JS 永不淘汰，Any AI/工具都懂，配合 GPT 出 HTML 点击化 🟡（分阶段适度）
- **合规**：无用户数据、无 cookie，隐私合规简单 ✔
- **已有技术栈**：作者已会用 HTML/CSS/JS（哥飞第0步）✔

---

## 换栈触发条件（什么时候需要重新评估）

1. 若后期要加"账号体系 / 数据持久化 / 付费订阅" → 需引入后端框架 + 数据库
2. 若内容规模和技术性复杂度明显上升（如做到多核对、多模块开发者工具箱）→ 可考虑上轻量静态框架
3. 若需大量交互（如折线图、实时协作）超出原生 JS 舒适区 → 再引入框架
