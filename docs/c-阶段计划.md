# c-阶段计划：Base Converter

> 依据 Vibe_Coding 立项门。由 `b-功能清单.md` 拆出，只给大阶段不深化技术。
> 关联：`b-功能清单.md`（上游）、后续 `d-技术选型.md`（下游，选型后再细化实施）。

---

## 为什么这么排

核心是"**先跑通最小可用闭环**"。进制转换里 BIN/DEC/HEX 是最常见、词也最有价值的三种；
先把它们做成一个能用的 MVP 快速上线，拿到真实流量反馈，再补 OCT、ASCII 和长尾内容。
避免一上来就要做全所有进制、所有花哨功能，拖到迟迟不上线。

---

## 阶段划分（大阶段）

### M0 · 立项（进行中）
- **内容**：产品定位、功能清单、阶段计划（就在于们的当前阶段）
- **判定**：'a/b/c 三个文档落盘，走完立项门

### M1 · MVP 上线（核心）
- **功能**（来自功能清单）：
  - F1 三进制互转：BIN ↔ DEC ↔ HEX（核心）
  - F2 复制结果
  - F4 首页 / 导航 + 这几个核心词的 TDK
- **目标**：一个能打开、能算、能复制的最小站，部署到 Vercel，提交 GSC
- **验收**：首页能算 BIN/DEC/HEX；负数和非法输入不崩；复制可用；上线 + 提交 GSC

### M2：补全转换面 + 内容
- **功能**：
  - F1 补 OCT（四种进制全排列互转）
  - F3 ASCII 转换块
  - F5 助记/说明区（长尾内容）
- **目标**：站形态完整，覆盖更多长尾词，为收录后的流量铺路

### M3：多页 / 长尾词落地 + SEO 打磨
- **功能**：每个核心转换做成可被搜到的落地结构（命中 `binary to decimal` 等词），完善 TDK / sitemap
- **目标**：从"一个工具"变成"能承接多个长尾词的多页小站"，走完收录 → 观察流量

### M4：反馈后优化
- **依据** GSC / GA4 数据，把出流量的词对应的页面做深、做更好用，开始考虑后续变现/矩阵
- **可选项**：接入广告或订阅（在数据有流量后再做，不在 MVP 范围）
