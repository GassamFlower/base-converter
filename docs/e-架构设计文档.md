# e-架构设计文档：Base Converter

> 依据 Vibe_Coding 立项门（架构设计部分），结合本项目的"纯静态无后端"现实做适配裁剪。
> 关联：`d-技术选型.md`（上游）、`AGENT_CONSTITUTION.md`（下游）。

---

## 0. 项目技术基线（本架构的一切前提）

- **纯静态**：无后端、无数据库、无环境变量依赖。
- **部署**：Vercel（一个 Git 仓库，静态文件直接托管）。
- **领域逻辑**：原生 JS 单一公共模块 `convert()` 完成全部进制换算。

> 因无后端/无数据库/无接口，本文档针对"目录结构 / 静态页 / 公共模块 / SEO 结构 / 维护边界"给出规则。接口响应、数据库、权限、日志等章节在本项目不适用，直接标注"不适用"。

---

## 2. 目录结构规则

```
base-converter/
├── index.html            # 首页（核心进制互转 + 导航）
├── styles.css            # 全站样式（或内嵌，依规模而定）
├── app.js                # 领域逻辑（convert 函数）+ 事件绑定
├── ascii.html            # 次要页：ASCII 转换（可选 M2 后）
├── docs/                 # 项目过程文档（立项/选型/架构/宪法）
├── sitemap.xml           # 提交给 GSC
├── robots.txt
└── .gitignore
```

**每个目录/文件职责（放什么 / 不放什么）**
- `index.html`：只放首页结构 + 调用 `app.js`；不放领域逻辑。
- `app.js`：放 `convert()` 与 UI 绑定；**不**放页面文字 / 样式。
- `docs/`：只放项目过程文档，**不**放运行时依赖。
- 静态资源（如果后续多个页面）放 `assets/`，js / css 分目录。

---

## 3. 公共模块（核心逻辑）

**`convert(value, fromRadix, toRadix, options)`**

- 职责：一切进制换算、ASCII、BigInt 大数处理唯一入口。
- 规则：所有 UI 只调用它，**不允许**各页面各自实现一套换算。
- 例外扩展：未来加 ASCII/字节，也在 `convert` 里加分支，不新造函数。

---

## 4. 页面 / URL 规则（针对 SEO）

- 每个核心关键词一个可访问地址：`binary-to-decimal` / `hex-to-binary` 等（M3 做多页时用）。
- 首页命中主要目标词：`binary to decimal`、`decimal to binary`、`hex to binary`。
- 每个页面：独立 `<title>` / `<meta name="description">`，命中对应关键词，`canonical` 指向唯一地址。
- `sitemap.xml` 列出全部可收录页面，`robots.txt` 允许爬取并指向 sitemap。

---

## 5. 错误处理与边界

- 非法输入（`dec` 输入字母等）：**不清零、不崩溃**，显示提示或留空。
- 超出 64 位 / 安全整数：用 **BigInt** 处理，不自溢出。
- HEX 常见 `0x` 前缀容忍；负数用对应进制的表示（如二进制补码）。
- 剪贴板被拒：降级为"选中文本让用户自己 Ctrl+C"。

---

## 6. 前端框架复用边界

- **必须用**：原生 HTML/CSS/JS、`encodeURIComponent` 等。
- **可封装**：视觉样式可抽简单 CSS 变量；复制/格式化可做轻量 helper。
- **禁止自造** 框架 / 路由 / 虚拟 DOM（用原生就够，不引入玩具框架）。

---

## 7. 新增模块规则（M2/M3 扩展时）

新增一个转换器，只需：
1. 在 `index.html`（或多页中）加一个 section。
2. 复用 `convert()` 接线 UI（输入框 → 结果）。
3. 加对应页面的 TDK + 自由 sitemap 条目。
4. 没有其他系统要改（无需后端 / 库 / 配置）。
