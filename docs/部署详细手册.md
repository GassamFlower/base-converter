# 📦 静态小站部署详细手册（Vercel + GSC）

> 专门针对「哥飞」套路里的**纯静态、无后端小工具站 / 单页站**的部署流程。
> 只要你的站是纯 HTML/CSS/JS（无数据库、无后端），就照这本手册走。
> 适用：本项目所有后续的站（base-converter、meme 独立站等）。

---

## 0. 适用前提

- ✅ 纯静态：一个或多个 HTML + CSS + JS，**无后端、无数据库**
- ✅ 有 GitHub 账号
- ✅ 想免费上线 + 被 Google 收录

> 如果你的站是 Next.js / 后端 / 需要数据库，见本文末尾「不适用的情况」。

---

## 一、第一次部署（首次完整流程，以后站都一样）

### Step 0 · 在 GitHub 建仓库
1. 打开 https://github.com/new
2. Repository name 填**项目英文名**（如 `base-converter`、`meme-maker`）
3. 设为 **Public**（静态站、SEO 需要公开可达）
4. **不要**勾"Add README / .gitignore"（避免跟你本地已有文件冲突），直接 Create

### Step 1 · 本地项目已是 git 仓库（Vibe_Coding 已做）
如果你项目文件夹里已经有 `.git/`（我会为你 `git init` 过），跳过 init 直接接 remote：
```bash
cd 你的项目文件夹
git remote add origin https://github.com/你的用户名/仓库名.git
git push -u origin main
```
> 第一次 push 会弹窗让你登录 GitHub 授权。如果你本地还没有 commit，先 `git add -A` + `git commit` 再 push。

### Step 2 · Vercel 一键部署（免费）
1. 打开 https://vercel.com ，用 **GitHub** 账号登录（如果没有先注册）
2. 点 **Add New… → Project**
3. 在仓库列表里点选你刚建的仓库（如 `base-converter`）
4. Framework Preset 选 **Other**（纯静态不需要框架预设）
5. 什么都不改，直接点 **Deploy**（绿按钮）
6. 等 1~2 分钟，Vercel 会给一个网址，类似：
   ```
   https://base-converter-xxxx.vercel.app/    ← 注意：带随机后缀
   ```
   这就是你站点的**线上真实地址**。

### Step 3 · 回填真实网址（关键，别漏）
Vercel 给的地址带随机后缀（`-xxxx`），但你的源码里 canonical / sitemap / robots 写的是占位网址。**必须改回真实地址**，否则 SEO 用的是错地址。

用编辑器打开这三个文件，搜 `base-converter.vercel.app` 之类占位，全部替换成真实网址：
1. `index.html` 里的 `<link rel="canonical" href="...">`
2. `sitemap.xml` 里的 `<loc>` 和 `Sitemap:` 行
3. `robots.txt` 里的 `Sitemap:` 行

替换完后重新推代码：
```bash
git add -A
git commit -m "chore: 更新 canonical/sitemap 为真实上线网址"
git push
```
Vercel 监测到 push 会自动重新部署，约 30 秒生效。

### Step 4 · 验证线上能访问
浏览器打开「你的真实网址 + /sitemap.xml」：
- `https://base-converter-xxxx.vercel.app/sitemap.xml` 能看到一份 XML 表示部署 OK
- 打开 `你的真实网址` 能正常看到首页 + 工具能用

## 二、首次提交 Google Search Console（让 Google 来收录）

1. 打开 https://search.google.com/search-console 用 **Google** 账号登录
2. 点 **添加资源** → 选 **网址前缀（URL prefix）**
3. 粘贴你的**真实线上网址**：`https://base-converter-xxxx.vercel.app`
4. 会要求**验证所有权**，用**最简单的方式「HTML 标签」**：
   - GSC 给一串 `<meta name="google-site-verification" content="XXX">`
   - 把这串 **一动不动** 粘进 `index.html` 的 `<head>`（`<title>` 之前随便一行）
   - 重新 push（Vercel 重新部署）
   - 回到 GSC 点 **「验证（Verify）」**通常立即通过
   - 验证通过后**建议把这条 meta 留着不删**（长期有效）
5. 验证通过后，左侧菜单点 **Sitemap**

### 提交 sitemap
1. 左侧 **Sitemap** → 点 **「添加新的站点地图」**
2. 输入框里**只填相对路径**：`sitemap.xml`（不要填完整网址）
3. 点 **提交（提交）**
4. 过一会儿会看到状态「发现」（近期抓取后可看到「成功」）

> 注意：sitemap 提交需要你**已经部署好线上网址 + canonical 回填完**，否则填了也抓不到。

## 三、每次做下一个站的通用流程（速查）

> 以后每做一个新站，只重复这一小段，不用重读全文：

1. **建站**：写好 `index.html` + `app.js` / `style.css` + `sitemap.xml` + `robots.txt`（canonical 先用占位 `https://仓库名.vercel.app`）
2. **推码**：GitHub 建库 → 本地 `git remote add origin …` → `git push`
3. **部署**：Vercel Import → Deploy → 记下真实网址
4. **回填**：把真实网址替换进 canonical + sitemap + robots → 重新 push
5. **收录**：GSC 添加资源（网址前缀）→ HTML 标签验证 → 提交 sitemap → 等收录
6. **统计（第二步可选）**：加 Google Analytics 4 的 script 到 `<head>`，推送后即可看访问量

## 四、常见坑与排查

| 症状 | 原因 | 解决办法 |
|---|---|---|
| sitemap 提交后一直没「成功」 | 没等 Google 抓取 / 没验证通过 | 等 24h 再看，或先 `curl` 线上 sitemap 确认能访问 |
| canonical 还是占位 | 忘了回填 | Step 3 重新 push 后等待 |
| 验证 meta 没生效 | Vercel 还没重新部署 | `git push` 后等 30 秒刷新再验证 |
| 网址带随机后缀想干净 | 嫌 `-xxxx` 难看 | 可选：在 Vercel 购买/绑定自定义域名（或不控，免费域名足够跑通） |
| git 第一次 push 报 "remote origin already exists" | 之前已加过 | 用 `git remote set-url origin 新地址` 覆盖 |

---

## 五、不适用场景

- 有后端 / 数据库 / 登录 → 需后端部署（非本手册）
- Next.js / Nuxt / SPA 构架 → 需在 Vercel 选对 Framework，不能选 "None"
- 要绑定自己的自定义域名且要干净专业的 URL → 在 Vercel 项目 Settings → Domains 添加你的域名
