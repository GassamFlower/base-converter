# a-立项文档：Base Converter（进制转换工具站）

> 依据 Vibe_Coding 立项门规范。本文档只做立项定义，不混技术选型 / 宪法 / 实现细节。
> 关联文档：`b-功能清单.md`（←本）、`c-阶段计划.md`（←b）。

---

## 1. 项目是什么

一个**纯前端的进制转换小工具站**，让用户在浏览器里把数字快速地在
**二进制（BIN）/ 十进制（DEC）/ 十六进制（HEX）/ 八进制（OCT）** 之间互相转换，
并附带 ASCII / Byte 等常见用途，一次搞定日常技术换算。

- 一句话：**"你要把 255 转成二进制？把 'hello' 转成 hex？都不用记公式，打开这个站就行。"**

## 2. 面向谁 / 解决什么问题

- **面向用户**：程序员、CS 学生、工程师、做题 / 调试 / 学习进制的人。
- **解决什么问题**：进制换算麻烦、记不住、用手算容易错。搜这些词的人带着明确的任务来，来了直接转换就走。
- 为什么做：锁定的 `binary to decimal` / `decimal to binary` / `hex to binary` 等词 CPC 较高、KD 低（低竞争 + 有广告价值），符合"一个关键词一个站"的练手目标。

## 3. 第一版做什么、不做什么（MVP 边界）

**做（第一版必须有的）**：
- 核心进制互转：BIN ↔ DEC ↔ HEX ↔ OCT（全排列可两两转换）
- 支持有符号负数、常见数值范围
- 简单的"复制结果"按钮
- 首页把常用转换器（尤其目标词那几个）放在显眼位置

**不做（第一版明确排除）**
- ❌ 不做账号 / 登录 / 收藏
- ❌ 不做数据库持久化（无后端，纯静态）
- ❌ 不做单位换算 / 日期 / 其他工具（那是后面工具箱的路）
- ❌ 不做移动 App / 桌面 App
- ❌ 不加广告 / 付费（先跑通流量）

## 4. 产品流程和用户路径

**主路径（核心）**
```
用户在 Google 搜 "binary to decimal" → 打开本站首页
→ 看到转换器 → 输入 1010 → 立即看到结果 10 → 点"复制" → 满足，离开
```

**次路径（长尾）**
- 用户搜带具体数字的词（如 "255 to hex"）→ 落地到对应转换器 → 转换
- 用户搜 "ascii to hex" → 进入 ASCII↔HEX 区块
- 学生解惑进来 → 页面带简单"进制是什么"的助记

## 5. 数据和业务对象清单

- **输入**：一个待转换的字符串（可为二进制/十进制/十六进制/八进制/ASCII）
- **输出**：转换后的字符串（目标进制 / ASCII）
- **转换规则**（业务对象）：
  - BIN ⇄ DEC ⇄ HEX ⇄ OCT 全排列两两转换
  - ASCII ⇄ BIN / HEX
  - Byte ⇄（可选，第一版不做）
- 每个转换器是"一个输入框 → 若干目标进制结果"，不互相持久化。

## 6. 技术路线（初步判断）

- **纯前端静态站**：单个 HTML（或少量静态文件）+ 原生 JS / 少量依赖。
- 无后端 / 无数据库 / 可静态托管（Vercel / GitHub Pages）。
- 原因是：纯工具、无状态、无需服务端，越简单越符合"技术选最简单"。
  > 已确定选型详见 `d-技术选型.md`（后续产出）。

## 7. 爆点差异（区别于竞品）

- **快**：单页即时算，无感。
- **全**：一个站覆盖 BIN/DEC/HEX/OCT 加常见的二/十六/ASCII。
- **含目标词 SEO**：首页与各转换器 url 直接命中 `binary to decimal` 等词。
- **干净**：专注工具，不带多余注册弹窗。

## 8. 里程碑

- **M0**：立项完成（本文档 + 功能清单 + 阶段计划）
- **M1**：MVP 上线（BIN/DEC/HEX 三种互转的核心可用）
- **M2**：补全 OCT 与全部两两转换 + ASCII
- **M3**：多页/长尾词落地 + 提交 GSC + 等待收录
- **M4**：数据反馈后优化（哪个词出流量加深哪个）

## 9. 验收规则（可检查）

- [ ] 首页能打开，无报错
- [ ] BIN/DEC/HEX/OCT 两两转换正确（人工几个用例 + 边界）
- [ ] 支持负数、常见范围输入
- [ ] "复制"按钮可用
- [ ] 目标核心词的 TDK 写对
- [ ] 无账号无后端，纯静态
- [ ] 框架/目录符合架构设计文档
- ** 部署到 Vercel 并提交 GSC**
